# Speech-following design and validation

Follow Voice is implemented as an optional macOS 26+ feature tracked by Bean `cueglass-2mil`. CueGlass keeps its macOS 14 deployment target. Deterministic tests and a macOS 14-target build do not establish live recognition quality; human-speech acceptance remains pending as recorded below.

## Native APIs and permission boundary

Apple's [SpeechAnalyzer](https://developer.apple.com/documentation/speech/speechanalyzer) and [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber) support on-device streaming transcription from macOS 26. `SpeechVoiceSource` is marked `@available(macOS 26.0, *)`; the operator creates it only inside an availability check when `SpeechTranscriber.isAvailable` is true. The UI is absent on macOS 14–25 and when the device reports transcription unavailable.

The system adapter checks `SpeechTranscriber.supportedLocales`, installed locales and `AssetInventory.status` without requesting microphone access or downloading models. It offers supported locales and explains that English is the validated language. A separate Install Speech Model button is the user's consent to call `AssetInventory.assetInstallationRequest(...).downloadAndInstall()`. The adapter displays the request's actual `Progress`, supports Cancel, and rechecks readiness after installation. Apple's `.downloading` status remains a waiting state when the system is downloading or waiting for network conditions; a nil installation request is treated as the already-installed race and readiness is checked again. Installation errors show the localized system reason with network/storage retry guidance. It does not start microphone capture or analysis until model readiness is confirmed and the operator later presses Start.

Only explicit Start checks `AVAudioApplication.recordPermission` and requests microphone access when permission is undetermined. A denial prevents capture and offers a link to Privacy & Security → Microphone. `NSMicrophoneUsageDescription` and `com.apple.security.device.audio-input=true` are included in the local plist/entitlement and tracked iCloud example/entitlement. Start fails closed if the built app has no nonempty usage string. The actual owner-copied iCloud plist remains gitignored and must be refreshed from the example; see [iCloud owner setup](../ICLOUD_SETUP.md).

Apple's [Speech permission guidance](https://developer.apple.com/documentation/speech/asking-permission-to-use-speech-recognition) applies to `SFSpeechRecognizer` and server recognition. Follow Voice uses `SpeechAnalyzer`/`SpeechTranscriber`; it does not call `SFSpeechRecognizer.requestAuthorization` and adds no `NSSpeechRecognitionUsageDescription`.

## Alignment and shared playback

`VoiceFollowCore` tokenizes the immutable prepared `ScriptSnapshot` into normalized words and UTF-16 source ranges. The active TextKit 2 viewport builds an immutable line/fragment table after measurement. It maps token offsets to layout Y coordinates and invalidates the table whenever the viewport is configured for a new snapshot or layout. Transcript alignment and layout mapping stay outside display callbacks.

`PlaybackSession` remains the only timeline for preview, fullscreen and floating output. `PlaybackTimeline`'s optional voice ceiling lets its existing time-based motion glide toward a confirmed script position and stop at that point without per-frame recognition work. The configured maximum LPM caps glide speed. Volatile transcript updates do not seek; confirmed discontinuities use a jump. A bounded transcript accumulator and newest-buffer/result streams keep transient state finite. Stale decisions carry an epoch and are ignored after stop or manual input.

The policy holds on silence, low confidence, mismatches and loss of lock, and attempts local or whole-script reacquisition after skips and rereads. Confirmed advances also estimate the presenter's recent on-script cadence from layout distance and speech audio time. Faster delivery can raise the shared glide by up to 40% over the operator's configured baseline, with a small lead and smoothing; slow speech never lowers the chosen baseline, and a long pause eases the glide back toward it. Volatile-only, ad-lib, jump, and manual-control events do not increase pace. Manual pace/navigation/scrub/pause and layout changes close the mic, suspend voice priority, and pause the shared timeline at the operator's chosen position. Only Play/Space, spoken Resume during command pause, or the explicit Resume control may re-arm following. Switching to Timed Scrolling ends the voice session and starts the selected timed take; Follow Voice disables the timed deadline. Stop Follow Voice, Stop Take, window close, sleep, audio-device/configuration loss and errors stop the analyzer/engine, remove the tap, finish bounded streams and clear transcript memory. Stop preserves the selected locale's model-readiness state and the denied-microphone recovery state.

## Spoken transport commands

During an explicitly started English Follow Voice session, either “CueGlass” or “Prompter” can prefix “pause”, “resume”, “stop”, “stop following”, or “stop take”. “Stop” means Stop Following; the longer “stop following” phrase remains supported. The matcher accepts “CueGlass” whether the transcriber emits it as one token or “Cue Glass” as two. It checks the best transcript and up to three alternative interpretations for commands only; script alignment continues to consume the best transcript. This uses [SpeechTranscriber's alternative interpretations](https://developer.apple.com/documentation/speech/speechtranscriber/result/alternatives) when the `.alternativeTranscriptions` reporting option is enabled. English commands also use a contextual [DictationTranscriber](https://developer.apple.com/documentation/speech/dictationtranscriber) in the same SpeechAnalyzer, with [app-specific contextual strings](https://developer.apple.com/documentation/speech/analysiscontext/contextualstrings) for both wake phrases and command vocabulary. Its command-only results never enter script alignment. Three independent four-word windows carry each of the leading interpretations across incremental command-recognition updates, so the wake phrase and action do not need to arrive in one result or even in the same interpretation rank. A phrase is confirmed by its transcriber's audio-time finalization watermark or when its exact wording remains unchanged for 0.75 seconds. Each channel's watermark confirms only candidates from that same recognizer. The quiet-time check handles unchanged volatile results that Apple does not reissue as final results ([SpeechModuleResult finalization guidance](https://developer.apple.com/documentation/speech/speechmoduleresult/resultsfinalizationtime)). Either short “stop” phrase waits through the same 0.75-second window so “stop take” can complete. Adjacent word starts must be no more than 1.1 seconds apart and the total phrase span no longer than 2.5 seconds. Known confidence below 0.55 is rejected; when confidence is absent, one of the exact wake phrases and stable wording remain required. The matcher retains at most four normalized command words and timestamps for each of the three command hypotheses in transient memory. Revisions restart confirmation, and a pending command phrase is withheld from script alignment.

Spoken Pause freezes the shared timeline and suppresses transcript alignment while retaining the capture stream only to hear Resume or a stop command. Spoken Resume resets the alignment hypothesis at the last confirmed script token, then restarts the shared timeline. Manual playback/navigation input still closes capture and takes priority. Stop Following leaves the take paused; Stop Take calls the existing operator stop action. Other selected locales retain script following but do not enable English transport commands.

Speech/audio content is not written to logs, documents, files or preferences. Only the selected locale is an app preference. Capture buffers exist transiently in a bounded stream for analysis; no recording is produced or retained.

## Research evidence

The standalone experiment at `73ecfb6e40bcb0869e51eb9b38ad09513048eeda` showed feasibility using generated speech, not a live microphone or human speaker. Its macOS 27.0.1 M5 Max run reported a median position lag of two words, recovery from its scripted skip and reread, and a hold during silence. That result is algorithm evidence only; it does not establish human voice, room, microphone, latency, sustained-take or cross-Mac quality. The experiment's pure alignment/policy and deterministic scenarios were ported into `CueFlowCore`; its separate production timeline was not.

## 2026-10-15 startup and model-install follow-up

Two operator crash reports for Start Follow Voice showed a Swift actor-isolation trap from the AVAudioEngine realtime messenger queue into the audio tap closure. The tap now receives a file-level `@Sendable` handler that appends converted buffers without inheriting the source object's main-actor isolation. A macOS 26+ native regression invokes this handler from a background queue with the analyzer's required signed 16-bit PCM format and observes an `AnalyzerInput`.

The operator later reported a failed model-install attempt, but the earlier UI replaced the system error with a generic network message. The adapter now retains the system error text, exposes pending system downloads as a separate state, and treats a nil request as already-installed/no further work per [Apple's AssetInventory request documentation](https://developer.apple.com/documentation/speech/assetinventory/assetinstallationrequest%28supporting%3A%29?language=objc). The inspector adds a colored state badge and stronger action/label contrast. On the available macOS 27 host, a fresh DebugLocal build still targets macOS 14; 41 Core and 74 native tests pass, including the callback, installation failure, retry, and pending-model regressions. The operator must retry installation and explicitly Start on the rebuilt app; these APIs have not been retested with a live model download or microphone after the fix.

## 2026-10-15 command-channel follow-up

The operator confirms ordinary script speech follows while spoken commands remain unrecognized. Inspection found that the contextual command recognizer's incremental results were evaluated one result at a time, so a wake phrase and action split across updates could never match. The command matcher now keeps three independent four-word rolling windows, separate from script alignment, and has deterministic tests for split “CueGlass / pause”, “Cue / Glass / stop take”, and an alternative “Cue Glass / pause” across updates. A focused native coordinator test exercises a command-only pause update without script words. The operator later confirmed command recognition works and approved “Prompter” as an additional wake phrase. Live confirmation of each wake phrase, Stop Following/Stop Take outcomes, and false-positive resistance remains part of the manual acceptance matrix.
